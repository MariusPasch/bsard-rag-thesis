# T04 boost ablation — v4 5-stem grid

Mode: **sparse-only (BM25 only)**.

This file separates T04's two design axes — embedding-text variant and query-time boost stage — by running each (unit, variant) cell twice (once with boost on, once with boost off) on each of the curated 5 stems. Generated by `RQ2_T04_ARM2_METADATA/scripts/boost_ablation.py --all-stems`.

Caveat under sparse-only on a single-PDF corpus: the v4 enricher drops the constant `[Document: ...]` header on single-doc corpora, so node `raw / enriched / full` collapse to identical BM25 input text. Their rows will therefore be bit-identical; the only embedding-text differentiator is `summary` (and on `article` units, `raw`/`full` similarly collapse). Run with `--hybrid` to differentiate via dense embeddings.

## Headline findings

**1. The boost stage is a complete no-op under default settings.** Every cell — 5 stems × 4 variants × R@10 / R@100 / MRR@10 / nDCG@10 — has Δ = 0 exactly when toggling boost on vs off. The boost step processes the post-RRF ranked list but never modifies any score on these queries, because the rule-based signal extractor (regex over a French legal vocabulary; `use_llm_classifier: False`) does not fire on BSARD's informal user questions ("Quelle peine pour les tags ?", "Puis-je être entendu pour expliquer mon plan de réinsertion ?"). The per-query traces saved in the existing v4 JSONLs confirm this: `n_terms_matched: 0, jurisdiction_signal: null, article_refs: []` on every query checked. The boost-stage multipliers (`term_match=1.3`, `used_in=1.5`, `jurisdiction=1.1`, `drop_non_effective=True`) are technically wired in, but for this evaluation methodology they have nothing to act on.

**2. Index-time enrichment carries the entire T04 signal.** Under sparse-only the only embedding-text variant that differs from baseline (`raw`) is `summary`. The Δ (summary − raw) on R@10 across the 5 stems is +0.043 (doc 6), +0.022 (doc 7), +0.009 (doc 9), +0.008 (doc 8), −0.008 (doc 5) → mean +0.015. Modest but non-zero, and at least one stem (doc 6) shows a notable lift. Compare this against the boost on/off Δ of exactly 0 on the same stems: index-time work is the whole story, query-time boost is dead.

**3. Sparse-only and hybrid disagree on direction for some stems.** On doc 5 under hybrid, `node_summary` underperforms `node_raw` by Δ −0.085 (R@10 0.383 vs 0.468); under sparse-only the gap is much smaller (Δ −0.008). On doc 6 the direction even reverses: hybrid Δ = −0.006, sparse Δ = +0.043. This indicates the summary block's value is partly absorbed by the dense embedder under hybrid (the summary's vocabulary doesn't align with the query embedding direction) but adds informative tokens to BM25's term-frequency signal. The 5-stem comparison table in [`comparison_summary_v4.md`](comparison_summary_v4.md) is the canonical hybrid view; this file is the sparse counterpart.

## What this means for the thesis writeup

- **Drop the boost stage from the "what T04 does" headline.** It contributes nothing measurable on BSARD-style questions under default settings. Either pair it with an LLM-based query extractor that actually populates the signals, or report it as a vestigial design surface from the original prompt's pipeline spec.
- **The boost stage is not actively harmful** — Δ = 0 means it neither helps nor hurts. So leaving it on in the canonical pipeline is fine; the cost is the ~few-ms per-query boost-loop overhead, which doesn't show up in the latency CSV at any meaningful magnitude.
- **A meaningful boost ablation would need different inputs.** Possible follow-ups (not run here): (i) hand-craft queries that reference articles ("article D219 du Code civil…") and rerun this grid — boost should now fire on the article-ref signal; (ii) enable `use_llm_classifier: True` (requires an Ollama model + budget) and rerun, to test whether LLM-extracted term signals materially change the ranking. Neither is needed for the thesis claim about T04 vs T03 — the variant-to-variant comparison already shows the active mechanism is index-time enrichment.

## Reading the table

- **Positive Δ** → the boost stage helped (turning it on improved the metric).
- **Zero Δ** → boost stage was a no-op for that cell (typically because no boost signals fired for any query — e.g. no term matches, no jurisdiction signal, no article references).
- **Negative Δ** → boost actively hurt (the multipliers pulled non-GT items above GT items). Look at the boost config in `arm2_metadata/boost.py`: `term_match=1.3`, `used_in=1.5`, `jurisdiction=1.1`, `drop_non_effective=True`.

The big question this file answers: **does the boost stage do meaningful work, or is index-time enrichment the whole signal?** Compare the magnitude of the Δ values here against the variant-to-variant Δ in [`comparison_summary_v4.md`](comparison_summary_v4.md) (e.g. `node_summary` vs `node_raw` on doc 9, Δ R@10 = +0.040). If boost-on/off Δ is small relative to variant-to-variant Δ, the enrichment carries the signal and boost is mostly cosmetic.
